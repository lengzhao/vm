# D3 MVCC 与有序并行执行实施计划

> 按用户已确认设计在当前 dev 工作区实施；不提交现有未提交变更。

**Goal:** 通过可选插件提供按键冲突检测和与输入顺序串行执行一致的批量调用。

**Architecture:** state/mvcc 同时提供 StateStore 和独立 SnapshotStore（快照事务可 Validate）。engine/default 额外提供 TransactionExecutor，在调用方事务内执行完整跨合约树但不提交。batch/ordered 只依赖 SnapshotStore 与 TransactionExecutor，在有界窗口并行推测，按输入顺序验证/提交；冲突项重新执行一次。Engine 原契约、state/memory、默认配置不变。

**Tech Stack:** Go 标准库、PluginKit、现有状态/执行/Gas 协议。

## 已确认范围与边界

- 同一批次无外部并发状态写入、合约产物替换；各请求及链上下文在调用期间不可被调用者修改。相同插件实例串行接收批次。
- 合约必须满足确定性策略，宿主插件可信且不得产生事务外副作用。超时/资源故障不属于共识确定性保证。
- 每个成功交易独立提交；失败交易不提交。整体取消/基础设施或回滚错误停止批次，保留已提交前缀，无整批原子承诺。
- 固定输入顺序决定提交及最终结果/事件顺序，不使用完成时间。失败与只读推测也验证访问集合，避免过期失败/结果。
- 窗口大小由 workers 限制（默认 4，范围 1–64），maxBatch 默认 1024，范围 1–65536；每窗口全部执行结束再提交，冲突只做一次顺序重执行，不无限重试。
- MVCC 用不可复用的每键版本令牌，包含缺失、删除与 ABA；读写集合唯一排序，保留副本/取消/关闭/回滚语义。

## 实施与审查修正

- MVCC、事务执行、批次调度及真实装配已实施；新增独立门面 engine/batched 仅组合 Engine 与 BatchExecutor，使现有 assembly 根节点入口可构造完整图。两种能力和生命周期仍分别由 PluginKit 管理，core.Engine 不扩大。
- 首轮独立审查发现推测执行的基础设施错误被当成业务失败继续处理。先补失败回归，现只允许明确业务分类作为 item.Err，遍历组合错误所有分支；容器清理失败/状态错误/取消/未知错误停止并清理未提交窗口，保留已完成前缀。
- 加载错误原先在 ExecuteTransaction 中缺失 Execute 的包装，现共用 loadExecution，并先失败再通过错误一致性回归。
- 空地址/空函数原先为未分类错误，现单次与事务内执行均返回 INVALID_REQUEST（诊断 Message 保留）；真实对照包含非法请求及后续合法项，验证业务失败不中止批次。
- 严格策略不允许 strconv.Atoi/Itoa；真实测试改用显式 64 位 ParseInt/FormatInt，不放宽策略。
- 真实严格合约直接串行与 workers=1/2/4 对照已通过；独立审查及修正增量复核无剩余明确 P1/P2。最终全量普通、全量 race（assembly 236.753 秒）、go vet、git diff --check 通过；Docker 测试容器无残留。验收详见 todo.md 第十一批记录，变更未提交。
