# E2 独占写入与可恢复批次实施计划

**Goal:** 实施已批准的共享写入会话及与状态原子落盘的批次回执，实现同 ID/同内容重放和断点续跑。

**Architecture:** 新增窄能力 RecoverableBatchStore/BatchSession 与 RecoverableBatchExecutor；state/bbolt 增强状态层会话约束，batch/recoverable 复用有序推测窗口。会话获取等待旧事务结束，持有期间普通 Begin 和其它会话可取消地等待；窗口使用会话快照，原子提交状态及连续回执。状态/回执磁盘结果不确定仍隔离实例，重开查询同批次身份后核对。原 Engine/BatchExecutor 及默认配置不变。

**Tech Stack:** Go、PluginKit、现有 bbolt v1.5.0 和 MVCC。

## 实施步骤

1. core/recovery.go 定义批次身份（ID/摘要/数量）、回执（结果及稳定错误码/诊断）、独占会话和恢复执行接口；先写状态层独占/取消/普通入口阻塞测试。
2. Bolt 在普通事务结束与会话关闭时唤醒等待者；Stop/fault 失效会话。持久化批次元数据和连续逐项回执与状态同事务提交，读/失败项目也落回执。失败写入丢弃但验证观察集合。内存发布后不新增失败步骤。
3. batch/recoverable 冻结请求与显式链上下文，生成版本化请求摘要；固定产物身份。拒绝同ID不同摘要，恢复已记录前缀；复用窗口及冲突重执行，返回最终结果。无外部事件恰好一次承诺。
4. 单测先失败覆盖重复/冲突ID、取消、状态与回执原子性、无写/业务失败、提交前/后故障与重开、回执副本/整数精度/上限；真实合约和子进程恢复；PluginKit 最小能力验证与配置。
5. docs/recoverable_batches.md、presets/recoverable.yaml 及相关文档/TODO同步；独立只读审查。固定代码后按顺序全量普通/race/vet/diff，Docker显式启用。E1/E2均留工作区，不自动提交/推送。

## 边界

- 单文件、单实例；只有通过同一后端访问的状态入口受约束。原始数据库文件和可信插件代码仍在信任边界内。
- 批次不整体原子；每项状态+回执原子。先前业务失败同样有回执且不执行第二次，基础设施错误停止不落交易结果。
- 回执含Data/Events/Gas和稳定错误分类，不恢复底层Go cause身份。外部事件投递需调用者幂等处理。
- ID/请求/回执/批次累计字节有限制；回执首版不自动清理。不得把任意确定性上下文、产物替换或宿主副作用隐藏在重试中。

## 实施中的边界修正

- 未完成批次的持久标记跨重启保留。原始等待策略经审查补失败回归后改为：活动会话期间等待；无活动会话但有pending时，普通Begin立即报告带ID的ErrBatchPending。
- 首次结果与重放统一为JSON回执表示（UseNumber），补回归确认uint64事件不丢精度且Go数值表示一致；恢复API只承诺稳定业务Code/Message，不恢复Go cause。
- 累计回执额度改为后端可配置maxBatchReceiptMB（默认64，4–1024），允许重开提高额度后续跑，不改变批次摘要。单项4MiB、诊断1MiB。
- executionID是部署方显式声明的执行规则身份，输入指纹绑定它，但不自动证明任意自定义插件配置等价；原请求及产物身份须保留。不提供外部事件恰好一次或未完成批次自动遗弃。
- 新增14个E2测试函数，覆盖核心恢复路径、故障/进程退出、独占与持久fence、配额恢复、真实合约、输入副本及最小插件能力；定向race通过。独立只读审查及增量复核无剩余明确P1/P2，最终全量普通/race/vet/diff均通过，Docker回归启用且无测试容器残留；详见todo.md第十三批验收记录。E1/E2均留dev工作区未提交/推送。
